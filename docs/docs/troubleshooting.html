Common problems#

Symptom Cause Fix
The picker shows a card instead of your buttonsThe picker only works on its own armature, in Pose Mode.The card says what is missing, and its button fixes it: Enter Pose Mode, Pose "rig" (makes that rig active) or Use it for ... (gives this picker to the active armature). See The Armature Picker.
Some picker buttons say "Missing bone"Their bone was deleted or renamed in a way FlexSpace couldn't follow (for example after regenerating a rig).In Edit Mode, run Utils > Repair Bone Bindings, then pick a new bone for the ones still missing.
Some picker buttons are goneSync Bone Collections Visibility (sidebar, Armature tab) hides the buttons of bones in hidden collections.Show the collection, or turn the option off.
Some picker buttons look faded, or are gone, and don't selectTheir bones are hidden with H, and the picker's Hidden Bones (ghost icon in the header) is Dim or Hide.Unhide the bones (Alt+H over the picker), or set Hidden Bones to Show (they still can't be selected while hidden).
Some widgets are goneThe Widget Types menu (the eye icon at the end of the header) hides whole kinds of widgets.Turn the type back on there.
Some widgets are goneThey are on another page.Check the page selector in the header.
A widget has a dashed outline in Edit ModeIts binding doesn't work: the path is wrong, or it points to the wrong kind of property.Select it and read the note under its Data Path in the sidebar. See Binding Properties.
The top bar says ⚠ N broken or N unboundThat many widgets have a broken binding or none yet, on the pages that work in the current mode and with the active object.Click it: it selects and frames the next broken widget (on its page) and opens the sidebar's Widget tab. Fix its path there, then click again for the next one. The count is gone once all are fixed.
An operator button is redIts operator can't run right now, for example a Pose Mode tool with no armature in Pose Mode.Use it in the right mode, or pick another operator.
An operator button opens a menu instead of running, for example Add Modifier asks which modifierThe setting it needs is not passed. Buttons made before version 1.4 dropped a setting picked at the operator's default value (Add Modifier's Subdivision Surface).Select the button and set the setting again under Operator Properties, or pick the operator again with Pick Operator from UI.
A button asks "Run Untrusted Code?"The button runs code stored in the .blend file, and Blender's Auto Run Python Scripts is off (or the file is in an excluded folder).Click Trust and Run if you trust the file. FlexSpace asks once per session, and again if the script changes.
Shift+A does nothingWidgets are added in Edit Mode.Press Tab first.
A key does something unexpectedCanvas keys come first (see Shortcuts). Any other key goes on to Blender's own keymap, so your custom bindings apply.Check the key in Shortcuts, or in your own Blender keymap.
The widgets look wrong, too dark or too lightThe theme Appearance doesn't suit your editor, or a widget has Override Theme on and keeps its own colours.Check Appearance in View > Theme (Auto follows the Node Editor background). For a widget with its own colours, click Reset to Theme in its Style panel.

Note In the picker, the rig must also be in Pose Mode before Shift+A adds widgets, and your Pose Mode keys work as in the 3D Viewport.

Report a Bug#

Found something broken? Open Help > Report a Bug... in the canvas header (or Report a Bug in the add-on preferences).

  1. Write a title, what happened, the steps to make it happen again, and what you expected.
  2. FlexSpace adds the details for you: the Blender and FlexSpace versions, your system and GPU, the canvas, the modules and the last FlexSpace errors of this session.
  3. Click Open on GitHub: a new issue opens in your browser, filled in. Review it and submit it there.

No GitHub account? Click Copy Report and paste it in a comment on the product page or in an email.

Nothing is sent by FlexSpace itself, and your home folder in any file path is replaced by ~.
